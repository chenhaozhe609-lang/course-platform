# 理工课探 · 校园课程评价系统 PRD

> 版本：v1.1
> 日期：2026-06-04
> 状态：需求已确认，待出技术方案
> 产品名：**理工课探**（面向理工科学生的课程评价社区，"课探"= 课程探索）

---

## 1. 产品概述

### 1.1 一句话定位

一个面向在校学生的课程评价社区：学生匿名分享真实选课体验，帮助同学做出更好的选课决策。

### 1.2 背景与目标

选课信息不对称是校园普遍痛点：教务系统只有课程名和学分，缺少"这门课好不好、给分松不松、作业多不多"等真实体验。本产品聚合学生第一手评价，降低选课踩坑率。

| 目标类型   | 指标                | 说明                             |
| ---------- | ------------------- | -------------------------------- |
| 北极星指标 | 月活评价阅读用户数  | 衡量"帮人选课"这一核心价值       |
| 内容供给   | 累计有效评价数      | 评价数量与质量是飞轮起点         |
| 互动       | 评价点赞/有用标记率 | 衡量内容是否真正有用             |
| 留存       | 次月留存率          | 选课季前后波动，需结合学期周期看 |

### 1.3 目标用户

- **核心用户**：在校本科/研究生学生（同时是内容消费者和生产者）
- **管理角色**：平台管理员（内容审核、用户管理、数据导入）

---

## 2. 关键产品决策

| 决策点   | 结论                                                 | 理由                                                     |
| -------- | ---------------------------------------------------- | -------------------------------------------------------- |
| 身份验证 | **学号(作为账号) + 密码，自助注册**             | 不校验真实学号白名单，学号仅作唯一登录账号，降低注册门槛 |
| 匿名策略 | **前台匿名 + 后台关联注册账号**                | 前台不露身份；违规时可定位到注册账号并封号（非真实实名） |
| 一人一评 | **同一课程每位学生限评 1 条**（可编辑/可追加） | 防刷评、保证评价代表性                                   |
| 内容审核 | **先发布后审核（事后审核）**                   | 降低发布门槛，配合举报+管理员复核兜底                    |
| 技术栈   | **Next.js 全栈**                               | 前后端一体，开发与部署成本低，SEO 友好利于课程页被搜索到 |

## 3. 功能范围（按版本）

## 4. V1 详细需求

### 4.1 账号体系

**注册（自助）**

- 输入学号作为账号 → 系统校验学号是否已被注册
  - 已注册 → 提示"该学号已注册，请直接登录"
  - 格式校验：学号为 6–20 位数字/字母（仅格式约束，不校验真实名单）
- 设置密码（强度校验：≥8 位，含字母+数字）
- 可选：设置匿名昵称（不填则系统随机生成，如"匿名的考拉#3271"）

**登录**

- 学号 + 密码
- 失败 5 次锁定 15 分钟（防爆破）
- 登录态用 JWT / Session（见第 6 节）

**隐私边界**

- 学号**永不**对其他普通用户展示，前台只显示匿名昵称
- 管理员在审核/追责场景可见学号（即注册账号，操作留日志）
- 注意：因不校验真实学号，"实名追责"实为"追溯到注册账号"，可封号但无法关联现实身份；后续如需强追责可再接入校验（V2）

### 4.2 课程库

**课程数据模型（详见第 5 节）**

- 课程号、课程名、开课院系、任课教师、学分、课程类型（必修/选修/通识）

**课程列表页**

- 支持按 课程名 / 教师名 / 课程号 关键词搜索
- 支持按 院系、课程类型 筛选
- 列表项展示：课程名、教师、平均评分、评价数
- 排序：综合评分、评价数、最新

**课程详情页**

- 头部：课程基本信息 + 各维度平均分 + 评分分布直方图
- 评价列表：按"有用数/最新"排序，分页加载
- 当前用户若未评价 → 显著"写评价"入口；已评价 → "编辑我的评价"

**学生提交新课程**（V1）

- 搜索不到课程时，提供"提交新课程"入口
- 表单字段：课程名、任课教师、开课院系、学分、课程类型（学分/类型可选填）
- 提交后状态为 `待审核`，默认对其他用户不可见（提交者本人可见并可立即评价）
- 去重提示：提交时按 课程名+教师 模糊匹配，疑似重复则提示"是否就是这门课？"
- 审核：管理员通过后转为 `已上架`（审核能力在 V1.5 管理后台落地；V1 期间可由管理员直接在数据库/简易页面处理）

### 4.3 评分 + 文字评价

**评分维度**（星级 1–5，0.5 步进）

| 维度     | 含义                       |
| -------- | -------------------------- |
| 综合推荐 | 总体是否推荐选这门课       |
| 给分情况 | 1=给分极严 … 5=给分很松   |
| 作业负担 | 1=作业极多 … 5=几乎没作业 |
| 收获程度 | 学到东西的多少             |

**文字评价**

- 必填，限制 10–2000 字
- 可选标签（快捷标记）：如"考试简单""点名严格""老师好""硬核"等
- 可选：标注修读学期（如 2025 秋）

**编辑/追加**

- 一人一评，可随时编辑
- 支持"追加评价"（结课后补充，展示为时间线，不覆盖原文）

### 4.4 互动

- **点赞**：对评价点赞 / 取消，实时计数
- **有用标记**：独立于点赞，用于排序权重（"X 人觉得有用"）
- **评论**：对某条评价发表评论（楼中楼一层即可，V1 不做无限嵌套）
  - 评论同样匿名展示
  - 评价作者可见"有人评论了你的评价"提醒（V1 可简化为个人中心红点）

### 4.5 个人中心

- 我的评价（可编辑/删除）
- 我点赞/收藏的评价
- 我的评论
- 账号设置：修改昵称、修改密码、退出登录

## 5. 数据模型（初稿）

> 关系型数据库（PostgreSQL 推荐）。以下为核心表，字段后续随开发细化。

```
User              用户
  id, student_no(唯一,作为登录账号), password_hash,
  nickname, role(student/admin), status(正常/封禁),
  created_at, last_login_at

Course            课程
  id, course_no(可空,学生提交时可无), name, teacher, department,
  credit, type, status(待审核/已上架/已下架),
  submitted_by(提交者user_id,可空), created_at

Review            评价（一人一课一条）
  id, user_id, course_id,
  rating_overall, rating_score, rating_workload, rating_gain,
  content, tags(jsonb), term, status(可见/隐藏/待审),
  helpful_count, like_count, created_at, updated_at
  UNIQUE(user_id, course_id)

ReviewAppend      追加评价
  id, review_id, content, created_at

Comment           评论
  id, review_id, user_id, content, status, created_at

Reaction          点赞/有用（统一表）
  id, user_id, review_id, type(like/helpful), created_at
  UNIQUE(user_id, review_id, type)

Report            举报(V1.5)
  id, reporter_id, target_type(review/comment), target_id,
  reason, status, handled_by, created_at

AuditLog          管理操作日志
  id, admin_id, action, target, detail, created_at
```

**统计字段策略**：`helpful_count` / `like_count` 等冗余计数字段，写时更新 + 定时校准，避免每次聚合查询。

## 6. 技术架构（Next.js 全栈）

```
┌─────────────────────────────────────────┐
│  Next.js (App Router)                     │
│  ├─ 前端：React Server/Client Components   │
│  ├─ API：Route Handlers (/app/api/*)      │
│  └─ Auth：Auth.js (NextAuth) Credentials  │
├─────────────────────────────────────────┤
│  ORM：Prisma                              │
├─────────────────────────────────────────┤
│  数据库：PostgreSQL                        │
└─────────────────────────────────────────┘
```

**技术选型建议**

| 层       | 选型                                 | 说明                |
| -------- | ------------------------------------ | ------------------- |
| 框架     | Next.js 15 (App Router)              | 全栈一体            |
| 语言     | TypeScript                           | 类型安全            |
| 鉴权     | Auth.js (Credentials Provider) + JWT | 学号密码登录        |
| ORM      | Prisma                               | 类型安全、迁移方便  |
| 数据库   | PostgreSQL                           | 关系数据 + 全文搜索 |
| UI       | Tailwind CSS + shadcn/ui             | 快速搭建、风格统一  |
| 表单校验 | Zod + React Hook Form                | 前后端共用 schema   |
| 部署     | Vercel（目标）                       | 当前阶段本地开发为主，暂不部署 |

**安全要点**

- 密码 bcrypt/argon2 哈希
- 学号脱敏：前台接口绝不返回 student_no
- API 鉴权中间件统一拦截
- 防刷：评价/评论限流，关键操作幂等
- XSS：文字内容输出转义，富文本（V2）需白名单过滤

## 7. 内容安全与社区治理

- **事后审核**：发布即可见，管理员后台抽审 + 举报触发复核
- **敏感词**：发布时做基础敏感词过滤（命中转人工）
- **追责机制**：每条内容后台关联注册账号(学号)，违规可定位账号、封号（非现实身份）
- **申诉**：被处理用户可申诉（V1.5）
- **一人一评 + 登录态**：天然抑制水军
